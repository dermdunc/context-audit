# Decisions: Context Audit

## ADR Log

| Date | Decision | Rationale |
|---|---|---|
| 2026-07-22 | Initial scaffold as factory-output | A CLI that audits a docs/context folder for approximate token cost, redundancy between files, and staleness, stating its own limits plainly rather than overclaiming precision. |
| 2026-07-22 | Remote creation failed on first scaffold attempt (`gh`'s active account was `coderturtle`, not `dermdunc`); recovered by `gh auth switch --user dermdunc` + `gh repo create --source=. --push` | Every prior mini-project's scaffold succeeded silently switching accounts; this one didn't, for reasons not fully diagnosed (possibly a transient gh/keyring issue). Recorded so a future session isn't surprised by the same failure mode. |
| 2026-07-22 | Built from scratch (no source to extract — confirmed `half-life` has no measurement script, only workshop content): `lib/tokens.mjs` (chars/4 estimate), `lib/shingles.mjs` (word-shingle Jaccard similarity), `lib/staleness.mjs` (git-history-preferred last-modified date), `lib/scan.mjs` (recursive directory walk), `lib/audit.mjs` (orchestration) | Every measurement is explicitly disclosed as an approximation in its own code comment and in the README, borrowing `half-life`'s review-panel discipline (never claim more precision than the method actually has) as the design principle, not any of its code. |
| 2026-07-22 | Doubt-driven-development pass (single-model, `Explore` agent) found and fixed 11 issues across filesystem robustness, git staleness semantics, and CLI argument handling | Most consequential: an unreadable file or directory used to abort the *entire* scan rather than being skipped with a warning; binary content with a matching extension was silently scanned as garbage-but-plausible text (Node's UTF-8 decoder never throws on bad bytes); a code comment falsely claimed symlinks were disclosed when nothing actually detected them; the staleness fallback couldn't distinguish "git not installed" from "not a git repository" from "zero commits yet" from "git ran fine but this file just isn't tracked," collapsing all of them into one silent mtime fallback with no diagnostic. The most subtle fix: comparing raw mtime against the git commit date to detect uncommitted edits would have reintroduced the exact bug it was meant to fix (mtime is always newer than the commit date immediately after any fresh clone/checkout, even on a perfectly clean tree) — replaced with an actual `git diff --quiet HEAD -- <file>` check, which asks git directly rather than inferring from timestamps. Verified this distinction with dedicated tests for "freshly checked out, clean" vs. "genuinely has uncommitted edits," not just one happy-path case. |
| 2026-07-22 | Cross-model review (`codex exec --sandbox read-only`, gpt-5.5) found and fixed 8 more real issues | The claimed "uniform" negative-number rejection wasn't uniform: `--stale-days -1` (space-separated) was rejected by the argument parser's own "looks like a flag" guard before ever reaching range validation, while `--stale-days=-1` (inline) reached it correctly — fixed by only treating the next token as "missing, that's another flag" when it's an actual recognized option name, not merely something starting with `-`. A blanket "skip every dot-directory" rule silently broke the tool's own advertised use case (auditing a Skills directory, which conventionally lives under `.claude/skills/`) — narrowed to skip only the explicit `SKIP_DIRS` list. The repo's own CI smoke-tested `.` (the whole repo root), which reported a misleading ~100% "redundant pair" against its own `mind-palace/` mirror (a deliberate Hekton scaffold convention, not a bug) — CI now scans `docs/` specifically. `runAudit`'s range checks used `<`/`>` comparisons that silently pass `NaN` through undetected (a direct library caller, not just the CLI, could trigger this) — added explicit `Number.isFinite` checks. `--top`/`--stale-days` accepted fractional values with undocumented truncation behavior — now require whole numbers. The binary-detection threshold's `>` vs. the comment's stated `>=` semantics were inconsistent at the exact 1% boundary — aligned. Disclosed, not fixed: `git log` doesn't use `--follow`, so a renamed file's date can look newer than its content actually is — added to the README's "Known limitations" section, matching this tool's own stated design principle of disclosing measurement limits rather than silently being wrong. |
